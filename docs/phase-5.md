# Milestone: `Phase 5 — Chapter reader`

## Goal

Turn content pages into a real reading experience.

## Deliverables

- chapter page
- MDX rendering
- current-chapter sidebar
- Prev Chapter / Next Chapter navigation
- stable heading anchors
- working deep links

## Definition of Done

- the user can enter a chapter and read content
- the sidebar shows only relevant current-chapter sections
- prev/next works
- links to specific sections work

## Phase boundary

This milestone includes the **reader route and chapter-reading experience only**. It does **not** include Phase 6 rich content blocks like figures/captions, styled tables, columns, callouts, or audience-conditional block rendering beyond whatever already exists in plain MDX. It also does **not** include Phase 7 glossary hover cards or Phase 8 localization consolidation work.

---

## Issues

### 60) `P5-60 [XS] Define Phase 5 reader conventions`

**Objective:** lock the implementation conventions for the chapter reader before route and UI work begins.
**Scope:** canonical reader route shape, shell reuse expectations, sidebar scope, anchor behavior, and explicit non-goals.
**Depends on:** Phase 4 being complete.
**Done when:** there is a small implementation note or constants module defining:

- the reader route shape that matches current TOC-generated chapter links
- the rule that the reader must preserve existing locale and shell controls
- the rule that sidebar navigation is restricted to the current chapter
- the Phase 5 / Phase 6 boundary.

### 61) `P5-61 [S] Create the dynamic chapter reader route scaffold`

**Objective:** create the real reader route that matches the URLs already generated by the TOC.
**Scope:** dynamic language-aware chapter route under the existing book route space.
**Depends on:** P5-60.
**Done when:** the project has a working dynamic chapter route that matches the href pattern currently produced for chapter links.

### 62) `P5-62 [S] Generate static paths for chapter reader pages from content metadata`

**Objective:** make the reader route content-driven rather than hand-maintained.
**Scope:** static paths for all valid chapter entries in the active locales/books currently supported.
**Depends on:** P5-61.
**Done when:** reader pages are statically generated from chapter collection entries and their slugs instead of being manually registered.

### 63) `P5-63 [S] Load the current chapter entry by language and slug`

**Objective:** resolve the requested chapter entry safely and predictably at the page layer.
**Scope:** content lookup, scope validation, and safe missing-entry behavior.
**Depends on:** P5-62.
**Done when:** the reader page can resolve the correct chapter entry for the requested locale and slug, and fails safely when the entry is missing.

### 64) `P5-64 [S] Render chapter body content through the MDX pipeline`

**Objective:** turn chapter entries into readable pages using the already-installed MDX stack.
**Scope:** chapter body rendering only, without Phase 6 rich-content enhancements.
**Depends on:** P5-63.
**Done when:** a chapter reader page renders the actual MDX body of a chapter entry in the main reading area.

### 65) `P5-65 [XS] Preserve shared shell controls inside the chapter reader`

**Objective:** keep reader pages aligned with the existing shell experience.
**Scope:** shared layout integration, language switcher, audience switcher, and existing header controls.
**Depends on:** P5-61, P5-64.
**Done when:** chapter pages render through the shared shell structure and preserve the existing locale and reading-mode controls instead of becoming isolated pages.

### 66) `P5-66 [S] Add chapter-level orientation and contextual navigation`

**Objective:** make it clear where the current page belongs in the book.
**Scope:** breadcrumb-like context, current chapter/page labeling, and a visible return path to the TOC.
**Depends on:** P5-64, P5-65.
**Done when:** the reader page provides clear chapter-level orientation and a reliable path back to the book home / TOC.

### 67) `P5-67 [S] Extract heading metadata for the current chapter`

**Objective:** build the data source for current-chapter local navigation.
**Scope:** heading extraction from chapter content and normalized section metadata for the current page only.
**Depends on:** P5-64.
**Done when:** the reader page can derive structured heading data for the currently loaded chapter.

### 68) `P5-68 [S] Build current-chapter sidebar data from extracted headings`

**Objective:** transform raw heading data into navigation data suitable for the reader sidebar.
**Scope:** hierarchy handling, nested-section support, and sidebar-safe labeling for current-chapter sections only.
**Depends on:** P5-67.
**Done when:** the app can generate sidebar navigation data limited to the current chapter.

### 69) `P5-69 [S] Render the current-chapter sidebar`

**Objective:** expose intra-chapter navigation as part of the reading layout.
**Scope:** sidebar UI, current-chapter-only section listing, and reader-compatible placement within the page.
**Depends on:** P5-68.
**Done when:** the chapter reader displays a sidebar that shows only the current chapter’s relevant sections.

### 70) `P5-70 [XS] Add responsive fallback behavior for chapter-local navigation`

**Objective:** keep section navigation usable without letting it dominate small screens.
**Scope:** compact navigation behavior for narrower viewports, without drifting into Phase 9 polish work.
**Depends on:** P5-69.
**Done when:** current-chapter navigation remains accessible on smaller screens while preserving the reading surface as the primary focus.

### 71) `P5-71 [S] Add previous and next chapter navigation to the reader`

**Objective:** connect the reader flow across content-driven chapter order.
**Scope:** previous/next resolution from metadata and reader-page navigation controls.
**Depends on:** P5-63, P5-64.
**Done when:** reader pages show correct previous and next chapter links computed from content metadata.

### 72) `P5-72 [S] Add stable heading anchors to reader content`

**Objective:** make chapter sections addressable and linkable.
**Scope:** stable IDs for relevant headings and visible/usable heading-link behavior.
**Depends on:** P5-67.
**Done when:** relevant headings in the reader page have stable anchors that can be linked to directly.

### 73) `P5-73 [XS] Implement working deep-link behavior for chapter sections`

**Objective:** make section-specific links actually land in the right place.
**Scope:** same-page anchor navigation, direct-load hash behavior, and correct section targeting from chapter URLs.
**Depends on:** P5-72.
**Done when:** a URL pointing to a specific section inside a chapter opens the correct chapter and resolves to the correct heading anchor.

### 74) `P5-74 [XS] Add empty-state and missing-heading safeguards for the reader`

**Objective:** keep the reader safe when a chapter has sparse structure.
**Scope:** chapters with no headings, shallow heading structure, or missing sidebar-worthy sections.
**Depends on:** P5-67, P5-69.
**Done when:** the reader still works correctly when heading structure is minimal, and the sidebar fails gracefully instead of breaking or misleading the user.

### 75) `P5-75 [XS] Add Phase 5 verification pass for reader behavior`

**Objective:** close the milestone against the actual roadmap Definition of Done.
**Scope:** chapter entry works, MDX content renders, sidebar scope is correct, prev/next works, anchors are stable, and deep links resolve.
**Depends on:** P5-64 through P5-74.
**Done when:** the user can open a chapter, read it, navigate inside the current chapter, move to adjacent chapters, and use section-specific links successfully, with no Phase 6/7/8 leakage.

## Exit criteria for closing the milestone

Phase 5 should be considered complete only when all of the following are true:

- chapter reader routes exist and match the current TOC-generated chapter links
- reader pages are generated from chapter content metadata
- chapter MDX content renders successfully
- reader pages preserve the existing shared shell controls
- the page provides chapter-level orientation and a path back to the TOC
- the sidebar shows only relevant sections from the current chapter
- previous/next chapter navigation works from metadata
- relevant headings have stable anchors
- deep links to specific chapter sections work
- the milestone still contains **no Phase 6+ leakage** such as figure/caption systems, columns, callouts, audience-block rendering expansion, glossary hover cards, or localization fallback logic.
