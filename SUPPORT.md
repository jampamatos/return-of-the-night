# Support

## Purpose

This document explains how to ask for help, when to open an issue, and when to use a private contact path instead.

## Project stage

The repository is still in **Phase 1: repository foundation**.

That means support is currently handled on a best-effort basis. The project is still setting up its documentation, contribution flow, and governance baseline.

## Where to ask for help

For general project questions, setup problems, documentation confusion, or suggestions for improvement, open a GitHub issue in this repository when the topic is useful for future contributors as well.

Examples include:

- local setup questions
- unclear documentation
- bugs or regressions
- feature ideas
- repository workflow confusion

## When to open an issue

Open a GitHub issue when:

- the problem is reproducible
- the question is likely to help other contributors
- the repository documentation is unclear, incorrect, or incomplete
- you want to report a bug or propose an improvement

Before opening a new issue, check whether the topic is already covered by an existing issue, README section, or project document.

## What not to use issues for

- private security disclosures
- reports that contain secrets, tokens, credentials, or personal information
- conduct reports involving harassment or unsafe behavior
- sensitive matters that should not be discussed publicly

## Security issues

If you believe you found a security issue, do **not** report it in a public issue.

Use the process described in [`SECURITY.md`](./SECURITY.md).

## Code of conduct

All project spaces are governed by [`CODE_OF_CONDUCT.md`](./CODE_OF_CONDUCT.md).

Please keep support requests respectful, constructive, and focused on helping move the project forward.

## Private contact

For matters that should not be handled in public, contact the maintainer privately via [email](mailto:jp.coutm@gmail.com).
